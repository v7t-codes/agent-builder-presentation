# Market framing: the problem and segmentation

## The problem these tools are solving

- Baseline capability (model + loop + tool calling) is **not** production.
- Production requires connectors into real systems, permissioning, auditability, eval gates, and reliable execution environments.
- Most durable value shows up where the platform reduces **operator load**, not where it adds more “prompt routing.”

## How we break the market down (5 segment pages)

1) **Developer & SDK-first** (runtimes, SDKs/frameworks, computer-use tooling)
2) **No-code & visual** (UI builders + automation incumbents evolving into agent builders)
3) **Vertical-specific platforms** (domain outcomes + deep integrations + KPI-linked evals)
4) **Agent studios & “Human+ software”** (delivery + operations + reusable tooling)
5) **Overlay: “AI employees” narrative** (cross-segment packaging as labor)

## How we compare products (autonomy regime)

These four axes make the regime explicit:

- **Environment surface:** `API` / `Browser` / `Desktop` / `Multi` / `Voice`
- **Task complexity:** `Low` / `Med` / `High`
- **Time sensitivity:** `Batch` / `Operational` / `Real-time`
- **Risk + consequence:** `Low` / `Med` / `High`
